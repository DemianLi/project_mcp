MCP 的一問一答，這一版不握手

還是 Client 問、Server 答，還是一條管子。差別在：每一則問題都自己講清楚「我講哪一版、我會什麼」，Server 不再記得上一則。這頁用同樣的四張圖，把新舊兩版的差別畫出來。右邊一欄是備注——白話意思，加上去哪一頁學。

MUST不做就不合規 SHOULD可不做，要記在案 MAY隨你 常見做法非規格條文 新增這一版才有 刪除這一版拿掉 棄用還能用，排定移除

先講結論

變了什麼、沒變什麼

變了

  • 沒有握手。initialize 那三步整段刪除，版本與能力改放在每一則請求的 _meta。
  • Server 不再反問。要更多資料時，回一個「還缺這些」，由 Client 帶著答案重送。
  • 每個結果都要標 resultType。正常結果是 "complete"。
  • Server 必須會回答 server/discover。「你會哪幾版、會什麼」隨時可以問。

沒變

  • 一個 Client 只連一個 Server（1:1）。
  • stdio：Client 啟動子進程，一行一則，stdout 只准走 MCP 訊息。
  • tools/list 看菜單、tools/call 點菜。
  • 兩種錯誤：協議錯誤走 JSON-RPC error，工具失敗走 isError: true。
  • 工具安全條款：Server 四條 MUST、Client 五條 SHOULD，原封不動。

角色

連線不等於對話

角色沒變：Host 裡的每個 Client 只連一個 Server。變的是這條連線的意義——MCP 現在是 stateless1，同一條管子上可以交錯跑好幾段不相干的對話。

備注

  1. 1stateless 無狀態——處理一則請求需要的資訊全在那一則裡。Server MUST NOT 靠前面的請求建立上下文。去哪學：basic/index.mdx §Statelessness ↗
  2. 2_meta 請求附帶的中繼資料——io.modelcontextprotocol/protocolVersion 與 clientCapabilities 每則必帶；clientInfo SHOULD 帶。去哪學：basic/index.mdx §_meta ↗
  3. 3Host · Client · Server 三個角色——每一版都寫著 Client 與 Server 是 1:1。去哪學：architecture/index.mdx ↗
  4. 4connection ≠ session 連線不是對話——stdio 行程不是對話；Server 不可把「同一條連線／同一個行程」當成同一段對話的依據。去哪學：basic/index.mdx §Statelessness 的 Note ↗

Client ↔ Server 交互

管子上傳什麼：新舊對照

左邊是 2025-11-25，右邊是 2026-07-28，同一個階段排在同一列。握手那一列，右邊整段刪掉。

  • 握手沒了，1:1 還在。想先知道對方會哪幾版，就問 server/discover；不問也行，直接送，版本不合會收到 -320226，挑一個雙方都會的再送。
  • Server 不再往 stdout 寫請求。要更多資料時，它把問題裝在結果裡回給你；你帶著答案、用新的 id 重送同一個請求。
  • 拿掉的：ping、logging/setLevel、notifications/roots/list_changed。棄用但還能用的：Roots、Sampling、Logging12——最早要到 2027-07-28 以後的版本才可能移除。

ClientServer結果
只會新版（Modern）project_mcp（Legacy）失敗。stdio 上 Client SHOULD 先送 server/discover，讓失敗變得確定，再給使用者看得懂的錯誤。
新舊都會（Dual-era）project_mcp（Legacy）可用。探測拿到的不是新版錯誤、或逾時，就退回 initialize。

新版管子上的一來一回（取自規格 server/tools 範例的形狀，換成 get_issue）

→ Client {"jsonrpc":"2.0","id":7,"method":"tools/call","params":{
           "name":"get_issue","arguments":{"owner":"DemianLi","repo":"project_mcp","number":12},
           "_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28",
                   "io.modelcontextprotocol/clientCapabilities":{}}}}

← Server {"jsonrpc":"2.0","id":7,"result":{"resultType":"complete",
           "content":[{"type":"text","text":"{\"number\":12, …}"}],"isError":false}}

備注

  1. 5server/discover 探詢——回傳支援的版本、能力、身分。Server MUST 實作；Client MAY 先呼叫，stdio 上也拿它當新舊版探測。去哪學：server/discover.mdx ↗
  2. 6UnsupportedProtocolVersionError 版本不支援（-32022）——Server 不會那一版就 MUST 回這個，並列出自己會的版本。去哪學：basic/versioning.mdx ↗
  3. 7resultType 結果種類——每個 result MUST 帶。"complete" 是正常結果；舊版 Server 沒帶，Client MUST 當成 "complete"。去哪學：basic/index.mdx §ResultType ↗
  4. 8ttlMs · cacheScope 快取提示——清單類結果 MUST 附上：幾毫秒內算新鮮、能不能給共用代理快取（public／private）。去哪學：server/utilities/caching.mdx ↗
  5. 9MRTR · InputRequiredResult 多趟請求——取代 Server 主動發問。Server 回 input_required，裡面列出要問的事（elicitation、sampling、roots）。去哪學：basic/patterns/mrtr.mdx ↗
  6. 10inputResponses · requestState 答案、Server 的便條——重送時帶答案；requestState 原樣奉還、不准拆看。重送的 JSON-RPC id MUST 跟第一次不同。去哪學：mrtr.mdx §Client Requirements ↗
  7. 11notifications/cancelled 取消通知——stdio 沒有「每則一條」的通道可關，所以 Client MUST 用它取消；Server 取消後 MUST NOT 再為那一則送任何訊息。去哪學：basic/transports/stdio.mdx §Cancellation ↗
  8. 12Deprecated 棄用——Roots、Sampling、Logging 仍可用但排定移除。替代：路徑走工具參數、直接接 LLM API、log 寫 stderr 或 OpenTelemetry。去哪學：deprecated.mdx ↗
  9. 13stdio shutdown 關機——Client 關 stdin、等它結束，逾時再強制終止。Server SHOULD 在 stdin 關閉時馬上結束；意外結束時 Client SHOULD 重啟它。去哪學：basic/transports/stdio.mdx §Shutdown ↗
  10. 14Modern · Legacy · Dual-era 新版、舊版、雙版——2026-07-28 起叫 Modern；2025-11-25 以前靠握手的叫 Legacy。上面那張表就是規格的相容矩陣。去哪學：basic/versioning.mdx §Compatibility Matrix ↗

MCP Client 內部資料流

Client 裡面怎麼轉

和前一版一樣，一個問題要經過 Host、模型、Client 才出門。多出來的是中間那一段：Server 說「還缺資料」，Client 就去問人，再重送一次。

  • Client 變成要記更多事的一方。版本、能力、身分每則都要附；Server 發的「便條」（requestState）要原樣帶回去，不能打開看。
  • 快取交給 Client 決定。清單類結果附了 ttlMs，Client 在期限內可以不必再問；但規格說 SHOULD NOT 把 TTL 當成定時輪詢的鬧鐘。
  • Server 的自我介紹還是不能當真。工具 annotations 照舊 MUST 當不可信；新增的 serverInfo 也 SHOULD NOT 拿來做安全判斷18。

備注

  1. 15per-request fields 逐請求欄位——protocolVersion、clientCapabilities 必帶，少一個就是格式錯，Server MUST 回 -32602。去哪學：basic/index.mdx §_meta ↗
  2. 16elicitation 向使用者索取資料——這一版由 Server 裝在 inputRequests 裡；Client 要先宣告能力，Server 才能這樣問。去哪學：client/elicitation.mdx ↗
  3. 17human in the loop 人在迴路中——SHOULD 永遠有人能拒絕工具呼叫。這條沒變。去哪學：server/tools.mdx §User Interaction Model ↗
  4. 18clientInfo · serverInfo 自報身分——雙方自己報的，協議不驗證；只供顯示、log、除錯，SHOULD NOT 用來改變行為或做安全判斷。去哪學：basic/index.mdx §_meta 的 Note ↗
  5. 19self-correction 模型自我修正——工具執行錯誤 SHOULD 交給模型，它才有機會改參數再試。這條沒變。去哪學：server/tools.mdx §Error Handling ↗

MCP Server 內部資料流

Server 裡面怎麼轉

中間是新版 Server 處理一則 tools/call 的路；左邊是提早離開的出口；右邊是 project_mcp 今天做得到嗎——多數做不到的，卡在它用的 SDK，不是這份程式碼。

  • 「你是誰、講哪一版」從握手搬進每一則請求。Server 讀 _meta 決定怎麼回，MUST NOT 靠上一則請求。
  • 要更多資料就回 input_required，自己什麼都不存。要記的東西寫進 requestState 交給 Client 帶回來——但它會經過 Client，所以 MUST 當成攻擊者可改的輸入；影響授權時要做完整性保護（HMAC、AEAD）。
  • 跨請求的狀態，用明確的 handle 當參數傳。規格的非條文建議；project_mcp 留言分頁的 cursor 就是這個形狀。
  • 寫入操作受速率限制。add_issue_comment 限制在每分鐘 80 次、每小時 500 次（GitHub 公開限制），超過時回 isError: true 加 Remedy: RETRY 與 retryAfterSeconds，讀取操作無限制。

2026-07-28 對 project_mcp 的實裝限制

項目為什麼
SDK 天花板無狀態核心、server/discover、resultType、ttlMs／cacheScope四項都落在 SDK 層；本版依賴的 MCP Java SDK 只支援到 2025-11-25。
不受影響MRTR、移除 session、錯誤碼分區它不發 Server 請求、stdio 沒有 session header、失敗只走 isError 不自訂錯誤碼。
可自行處理tools/list 順序固定（SHOULD）今天依 Spring AI 掃描順序，沒有明確保證。

備注

  1. 20_meta validation 檢查逐請求欄位——少必帶欄位回 -32602；Server MUST NOT 依賴 Client 沒宣告的能力。去哪學：basic/index.mdx §_meta ↗
  2. 21error code allocation 錯誤碼分區——-32020～-32099 保留給規格：-32021 缺能力、-32022 版本不支援。-32000～-32019 是舊區，新實作 SHOULD NOT 用。去哪學：basic/index.mdx §Error Codes ↗
  3. 22JSON Schema 2020-12 參數表——這一版放寬 inputSchema／outputSchema，允許 2020-12 的任何關鍵字；structuredContent 可以是任何 JSON 值。去哪學：basic/index.mdx §JSON Schema Usage ↗ · JSON Schema 入門 ↗
  4. 23requestState Server 的便條——不透明字串，Server 自己定格式。MUST 視為攻擊者可控；影響授權或商業邏輯時 MUST 做完整性保護。去哪學：mrtr.mdx §Server Requirements ↗
  5. 24stateful tools · handle 有狀態的工具——協議沒有 session，要跨請求記東西就回一個 id，之後當參數傳回來。非條文的設計建議。去哪學：server/tools.mdx §Stateful Tools ↗
  6. 25SDK ceiling SDK 天花板——協議版本由 SDK 處理，Server 自己的程式碼碰不到。本版依賴的 MCP Java SDK 2.0 支援的最新版本是 2025-11-25，所以這一版的新要求要等 SDK 升級才能滿足。去哪學：modelcontextprotocol/java-sdk ↗
  7. 26stdout purity stdout 純淨——Server MUST NOT 往 stdout 寫非 MCP 訊息，這一版還加上 MUST NOT 寫 JSON-RPC 請求。log 可寫 stderr。去哪學：basic/transports/stdio.mdx ↗
